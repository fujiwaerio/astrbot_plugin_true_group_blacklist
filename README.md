# 真正的群黑名单

![Version](https://img.shields.io/badge/version-1.0.0-blue)
![AstrBot](https://img.shields.io/badge/AstrBot-%3E%3D4.28.1%2C%3C5-purple)
![License](https://img.shields.io/badge/license-MIT-green)

**不只是关闭 AI 回复：让黑名单群的消息与指令在进入 AstrBot 处理流程之前被丢弃。**

> 注意：本插件拦截入站事件，不阻止其他插件的定时推送或直接调用平台 API。上游 QQ/NapCat 仍可能接收原始消息。具体限制见下文。

## 功能亮点

- **入口拦截**：在共享事件队列入口丢弃命中事件，早于正常指令与插件处理。
- **指令也屏蔽**：普通消息、@、内置指令与插件指令统一处理。
- **无管理员例外**：群主、群管理员、AstrBot 管理员同样受限。
- **精确群匹配**：支持全局群 ID，也支持“平台实例 ID + 群 ID”。
- **面板管理**：通过 AstrBot 配置界面设置，避免被禁群内指令绕过。
- **无需额外依赖**：不修改 AstrBot 核心文件，禁用时解除本插件拦截。

## 工作原理

```text
平台接收与解析事件（本插件无法阻止）
            ↓
      AstrBot 共享队列入口
            ↓
      是否属于黑名单群？
       ├─ 是 → 丢弃，不进入后续流水线
       └─ 否 → 事件总线 → 指令 / 插件 / AI
```

在 AstrBot **事件队列入口**丢弃来自黑名单群的事件，而不是只关闭 AI 或在普通消息监听器里停止传播。显示名为“真正的群黑名单”，插件标识为 `astrbot_plugin_true_group_blacklist`。

## 安装与配置

### 方式一：ZIP 安装

1. 在 AstrBot WebUI 的插件管理页面选择从本地 ZIP 安装，上传发布包。
2. 打开本插件配置，保持“启用真正的群黑名单”为开启状态。
3. 在“群黑名单”列表中，每项添加一个群 ID，例如 `123456789`。默认列表为空，不会屏蔽任何群。
4. 保存配置，**重载本插件**。建议首次安装配置后重启 AstrBot，以清除旧的排队消息、已启动任务并确认启动日志显示入口拦截已加载。
5. 在该群发送普通文字、@机器人、`/help` 以及插件指令，均不应触发正常 AstrBot 消息处理；用未屏蔽群和普通私聊做对照。

### 方式二：仓库链接安装

在 AstrBot 插件管理的仓库链接安装入口填写：

```text
https://github.com/fujiwaerio/astrbot_plugin_true_group_blacklist
```

仓库根目录上传完整插件源码后即可使用此方式。不要填写单个文件的链接。

[GitHub 仓库](https://github.com/fujiwaerio/astrbot_plugin_true_group_blacklist) · [版本发布](https://github.com/fujiwaerio/astrbot_plugin_true_group_blacklist/releases) · [问题反馈](https://github.com/fujiwaerio/astrbot_plugin_true_group_blacklist/issues)

### 配置项

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enabled` | 布尔值 | `true` | 是否启用入口拦截 |
| `blocked_groups` | 列表 | `[]` | 每项一个群 ID 或 `平台实例ID\|群ID` |

配置示例（通过 WebUI 填写即可，无须手动创建文件）：

```json
{
  "enabled": true,
  "blocked_groups": ["123456789", "my_qq_bot|987654321"]
}
```

- `123456789`：屏蔽所有平台实例上 group_id 完全相同的群。
- `my_qq_bot|987654321`：只屏蔽平台**实例 ID**为 `my_qq_bot` 的连接上的此群。实例 ID 不是适配器类型 `aiocqhttp`；请以 AstrBot 平台配置或消息日志显示的实例 ID 为准。
- 群 ID 按字符串精确匹配；支持 Telegram 负数 ID 等不透明标识。不要填群名、用户 QQ 号或开启独立会话后带用户后缀的 session_id。
- 不注册任何群内管理指令，故不存在“管理员在被禁群发解禁指令”的例外。解禁请在 WebUI 删除该项并重载。
- 配置由 AstrBot 保存在 data/config 下，不写入插件目录。无需额外依赖。

## 拦截范围

对插件生效后、**经过 AstrBot 共享事件队列的新入站事件**：

- 黑名单群的文字、图片、语音、文件、@、唤醒词、内置指令、插件指令均不进入事件总线及后续流水线。
- 不区分发送者权限，AstrBot 管理员、群主及群管理员也不豁免。
- 不触发这条消息后续的 LLM 调用、回复、流水线历史记录或事件总线的 user_chat 日志。
- 已转换为 AstrBot 事件、且能从 group_id 或原始事件顶层 group_id 识别来源的群通知、请求，也一并丢弃。
- 正常私聊和未列入的群不受影响；若私聊/请求的原始事件明确关联黑名单 group_id，也会拦截。
- 不扫描聊天正文中的群号，不因为某人提到黑名单群就屏蔽其他会话。

## 必须了解的边界

这不是平台网络防火墙，也不等于退群：

1. QQ/NapCat/其他上游仍会接收到消息；适配器解析、下载媒体、原始调试日志或转换失败后的平台侧错误回复可能发生在入队之前，插件无法撤销。要完全不接收上游群事件，应在上游做群过滤或让机器人退群。
2. **不拦截其他插件的定时/主动推送、直接调用平台 API 发消息、绕过事件队列的监听器**，也不撤销已在执行的回复或 LLM 请求。本插件针对接收入口，不是出站防火墙。
3. 加载前已在队列中、已被总线取走或已开始处理的事件不追溯拦截。不删除历史数据库、已有文件或日志。
4. 本插件是全局入口保护，**不受会话插件白名单/插件集控制**。请通过本插件配置或全局禁用控制；不要依赖会话级开关停用它。
5. 如其他插件覆盖队列方法、持有安装前的入队方法引用，或未来核心不再使用同一队列，可能绕过此入口。无法识别群信息的异常事件会放行并给出一次不含消息正文的警告，避免破坏整个适配器接收循环。
6. 禁用/卸载会解除本插件的拦截。与其他队列包装器共存时不会覆盖其后来安装的方法，残留的本插件包装器会成为透明转发。

## 实现与兼容性

按官方插件规范提供 Star 子类、metadata.yaml、配置 schema、initialize/terminate 生命周期。通过 `Context.get_event_queue()` 获取共享 asyncio.Queue，仅在该**实例**上包装 put/put_nowait；不改 AstrBot 安装文件、不全局修改 asyncio.Queue。

官方普通消息过滤器无法保证在事件总线日志、唤醒和指令匹配之前执行，因此这里有意使用运行时队列方法包装。这属于需要随核心版本回归验证的实现，不是官方承诺稳定的过滤扩展点。

基于本机 AstrBot **4.28.1** 源码开发验证，声明范围 `>=4.28.1,<5`；不代表该范围所有版本和平台均经过实机验证。跨平台依赖统一群 ID；优先用于 OneBot/QQ，其他适配器请先做对照测试。源码和隔离测试随 ZIP 提供。

## 常见问题

### 拉黑后为什么还有群日报或定时消息？

定时任务属于主动发送，不经过此入站队列。请到对应插件中关闭该群的推送，不能用本插件代替出站限制。

### 为何不提供群内添加、移除黑名单的命令？

被禁群的指令也应被丢弃。为避免管理命令例外或权限绕过，统一使用 WebUI 管理。

### 如何确认生效？

检查加载日志显示“入口拦截已加载”，再用非机器人账号在被禁群测试，同时在普通私聊或未被禁群进行正常回复对照。单凭没有日志、没有回复，不能排除消息没有送达或机器人断线。

### 为什么普通消息过滤插件不能完全替代？

普通监听器执行时，事件可能已进入总线日志、唤醒和指令匹配。本插件把判断提前到共享队列入口，但仍无法提前到上游平台接收阶段。
